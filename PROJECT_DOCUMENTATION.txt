1. SYSTEM OVERVIEW & ARCHITECTURE
================================================================================

The Apex Banking Platform is an enterprise-grade distributed core-banking
system engineered with Java 17, Spring Boot 3, MySQL 8, Apache Kafka (KRaft),
OpenTelemetry (OTel), Prometheus, and Grafana.

Architecture Highlights:
- Database-per-Microservice isolation
- JPA Optimistic Concurrency Control (@Version) to prevent balance race conditions
- Distributed Idempotency Key validation to prevent duplicate debits on retries
- Asynchronous Event-Driven Choreography via Kafka
- End-to-End Distributed Tracing across REST HTTP and Kafka messaging
- Unified Observability (Prometheus Metrics, Jaeger Traces, SLF4J MDC Structured Logs)

2. DETAILED EXPLANATION OF EVERY COMPONENT
================================================================================

COMPONENT 1: common-dto (Shared Domain Contracts)
-------------------------------------------------
Directory: common-dto/
Role: Encapsulates shared domain objects, enums, DTOs, and Kafka events.
Key Files:
- AccountType.java: CHECKING, SAVINGS, BUSINESS, INVESTMENT
- AccountStatus.java: ACTIVE, SUSPENDED, FROZEN, CLOSED
- TransactionStatus.java: PENDING, COMPLETED, FAILED, REJECTED
- TransactionCreatedEvent.java: Immutable Kafka domain event with transaction ID,
  accounts, amount, currency, timestamp, and correlation ID.
- FraudAlertEvent.java: Kafka event emitted on suspicious transactions carrying
  risk score, risk level, rules triggered, and notes.
- TransferRequest.java: DTO carrying source, target, amount, currency, and
  the crucial idempotencyKey.

COMPONENT 2: api-gateway (Edge Router & Tracing Initiator)
----------------------------------------------------------
Directory: api-gateway/ (Port 8080)
Role: The single entry point for all external client requests.
Key Files & Responsibilities:
- LoggingAndTracingFilter.java:
  * Intercepts every inbound HTTP request.
  * Checks for "X-Correlation-ID" header. If missing, generates a unique UUID.
  * Injects correlation ID into the downstream request and client response headers.
  * Measures round-trip execution latency in milliseconds.
  * Emits structured SLF4J log lines at ingress and egress.
- application.yml:
  * Routes /api/v1/accounts/**        -> account-service:8081
  * Routes /api/v1/transactions/**    -> transaction-service:8082
  * Routes /api/v1/fraud/**           -> fraud-detection-service:8083
  * Routes /api/v1/notifications/**   -> notification-service:8084
- FallbackController.java: Returns structured HTTP 503 fallback responses.

COMPONENT 3: account-service (Core Banking Ledger & Balances)
-------------------------------------------------------------
Directory: account-service/ (Port 8081)
Database: apex_account_db
Role: Manages customer accounts, deposits, debits, credits, and ledger audits.
Key Files & Responsibilities:
- BankAccount.java:
  * Entity holding account details and balance.
  * Contains "@Version private Long version": Optimistic Concurrency Control.
    If two concurrent requests try to debit the account at the same millisecond,
    the first committer succeeds and increments the version. The second transaction
    fails with an OptimisticLockingFailureException, preventing double debits
    without performance-killing table locks.
- AccountAuditLog.java:
  * Immutable ledger recording balance before, balance after, amount, action type
    (ACCOUNT_CREATED, DEBIT, CREDIT), and reference ID for audit trails.
- AccountServiceImpl.java:
  * debitAccount(): Checks account status is ACTIVE, checks balance >= amount,
    subtracts balance, logs audit record, and updates Prometheus counter.
  * creditAccount(): Validates status, adds balance, logs audit record.
- GlobalExceptionHandler.java:
  * Translates business exceptions into standard HTTP error responses (400, 404, 409).

COMPONENT 4: transaction-service (Payment Orchestrator & Kafka Producer)
------------------------------------------------------------------------
Directory: transaction-service/ (Port 8082)
Database: apex_transaction_db
Role: Handles inter-account transfers, enforces idempotency, calls Account Service,
and publishes Kafka events.
Key Files & Responsibilities:
- TransactionRecord.java:
  * Maps the transactions table.
  * Features a UNIQUE INDEX on idempotency_key.
- TransactionServiceImpl.java:
  * Step 1 (Idempotency Check): Queries DB for idempotencyKey. If found, returns
    existing transaction record immediately without reprocessing.
  * Step 2 (Account Validation): Verifies source != target and calls Account
    Service to ensure both accounts exist and are ACTIVE.
  * Step 3 (Debit Source): Invokes REST call to debit source account.
  * Step 4 (Credit Target with Compensation): Invokes REST call to credit target.
    If credit fails, initiates a compensating transaction (re-crediting source)
    to guarantee zero money loss (Saga pattern).
  * Step 5 (Kafka Publish): Emits TransactionCreatedEvent to "bank.transactions".
- TransactionProducer.java:
  * Injects X-Correlation-ID into Kafka record headers.
  * Asynchronously logs topic, partition, offset, and transaction ID.

COMPONENT 5: fraud-detection-service (Real-Time Risk Scoring Engine)
--------------------------------------------------------------------
Directory: fraud-detection-service/ (Port 8083)
Database: apex_fraud_db
Role: Asynchronously evaluates every transaction against compliance rules.
Key Files & Responsibilities:
- TransactionConsumer.java:
  * Listens to Kafka topic "bank.transactions".
  * Extracts correlation ID and trace headers into MDC.
- FraudRuleEngine.java:
  * Rule 1 (High Value): Transfers >= $10,000 add +65 to risk score.
                         Transfers >= $50,000 add +90 to risk score.
  * Rule 2 (Round Amount Anomaly): Large round numbers add +10.
  * Risk Levels: LOW (0-29), MEDIUM (30-59), HIGH (60-84), CRITICAL (85-100).
  * If risk is HIGH or CRITICAL, publishes FraudAlertEvent to "bank.fraud-alerts".
- FraudAssessmentRecord.java:
  * Stores risk scores, rules triggered, and notes in MySQL for audits.

COMPONENT 6: notification-service (Customer Alert Dispatcher)
-------------------------------------------------------------
Directory: notification-service/ (Port 8084)
Database: apex_notification_db
Role: Listens to transaction and security events and dispatches alerts.
Key Files & Responsibilities:
- BankingEventNotificationConsumer.java:
  * Consumes "bank.transactions" -> formats Email transfer confirmation.
  * Consumes "bank.fraud-alerts" -> formats SMS urgent security alert.
- NotificationDispatcher.java:
  * Dispatches alert, logs structured SLF4J audit entry, updates Prometheus
    counters (tagged by channel and type).
- NotificationRecord.java:
  * Persists full notification history in MySQL.

COMPONENT 7: Infrastructure & Observability
-------------------------------------------
1. MySQL 8.0: Automatically executes docker/mysql/init.sql to create 4 databases:
   apex_account_db, apex_transaction_db, apex_fraud_db, apex_notification_db.
2. Apache Kafka: Single-node KRaft broker (zero ZooKeeper dependency).
3. Jaeger (OTel): Collects distributed traces at http://localhost:16686.
4. Prometheus: Scrapes all 5 services every 5 seconds at http://localhost:9090.
5. Grafana: Visual dashboards at http://localhost:3000 (admin / admin).

  as your project root and import as a Maven project.

6. POST-CREATION ADJUSTMENTS & TROUBLESHOOTING
================================================================================

1. MySQL Port 3306 Conflict:
   If port 3306 is occupied by an existing local MySQL service, edit
   docker-compose.yml: change "3306:3306" to "3307:3306".

2. Docker Memory Allocation:
   Ensure Docker Desktop is allocated at least 6 GB of RAM.

3. Kafka Initial Startup Delay:
   If microservices start before Kafka completes topic initialization,
   simply restart the dependent services:
   docker compose restart transaction-service fraud-detection-service notification-service
